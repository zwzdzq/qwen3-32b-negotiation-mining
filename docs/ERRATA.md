# 勘误

2026-10-29 公开整理时补充。

本仓库保留比赛期间的原始文档，**没有事后改写当时的结论**。以下几条早期判断已被后续实测推翻或削弱，阅读原始文档时请以本页为准。保留错误并标注更正，比悄悄改掉更能反映这轮实验的真实过程。

## 1. qlora 目录是 adapter，不是合并权重

- 原文位置：`docs/retrospective-preliminary.md` §9 第 11 条、§10；`docs/REPRO.md` §1。
- 实测更正：`/root/autodl-tmp/output/qwen3-32b-qlora` 是 **adapter**（536,991,984 字节，r=16 / alpha=32，含 checkpoint-500 / checkpoint-900）；完整合并权重在 `output/qwen3-32b-merged`，索引引用的 17 个分片齐全。因此原文「merged 目录很可能不存在」的说法错误。
- 来源：`docs/semifinal-prep-audit.md`（2026-10-15 核查）。

## 2. 「改 prompt 变差的根因是偏离 SFT 训练模板」未被证实

- 原文位置：`docs/retrospective-preliminary.md` §7 把该机理作为定论，并进一步推论「prompt 是已固化的接口契约，不是自由变量」。
- 更正：初赛的**训练 instruction 与推理 build_prompt 本就不相同**，所以「偏离训练模板」无法作为已证实原因，它只是与观测一致的假设之一。复赛中仅调整聊天模板与输出要求的 candidate_01 在同一 val24 上还有小幅改善，说明「prompt 侧必然是负收益」也不能当作普遍结论。
- **仍然成立的部分**：在同一 checkpoint 上，两轮 prompt 挑战的 TOTAL 确实从 0.6094 降到 0.4038 / 0.4953，这是实测结果。需要收回的是对机理的断言和过度推广，不是数据本身。

## 3. 本地评分器是代理实现，不是官方口径的精确复刻

- `src/val_score2.py` 有两处已知偏差（初赛复盘 §3 已自行修订）：ext 用 `F1 × α` 而非官方 `F1 × (0.7 + 0.3α)`；future 组合权重不是官方的 0.6 / 0.4。此外它使用贪心匹配而非官方的最大二部一对一匹配。
- 复赛使用的 val_score3 系列修正了公式与匹配方式，但 BGE 平均池化、字符级 ROUGE-L、500 token 的 BERTScore 截断等实现细节**仍未与官方实现逐项核实**。公式一致不等于实现一致。
- 结论：本地分只用于同流程 A/B 门控；任何「本地分 = 官方分」的说法都不成立。

## 4. 复赛实际推理配置与初赛文档的建议值不同

- 初赛文档曾建议复赛使用 `MAXC=8000 / MNT=4096 / BS=8`；复赛实际采用 **MAXC=12000、MNT=4096、BS=1**，训练 `cutoff_len=16384`。
- `BS=8` 从未在长文本 + 长输出的条件下验证过峰值显存；`MAXC=8000` 覆盖不了全部输入（复赛 train 最长 11803 字符）。**字符与 token 不是同一单位**，不能直接比较。

## 5. 「future_argument 截多补少」只是初赛兜底，不是复赛交付行为

- `src/inference.py` 的 `normalize_result` 会做长度对齐（多截少补）。
- 复赛最终交付要求数组天然等长、完整响应通过验收，**不依赖截断或占位补齐**，避免掩盖议题与 future 的对应关系错误。
